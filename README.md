# 剧本杀线上中控平台

AutoDM 机器人主控 + 人工 DM 介入 + 玩家自由拖拽线索托盘，纯 Web 实现，链接即房间。
界面为**手绘纸张拼贴风**（米色纸底 / 牛皮纸卡片 / 暗红标题 / 虚线边框 / 胶带压角 / 手写体），并会**跟着剧本画风变色**（纸张 / 雨夜悬疑 / 古风 / 校园 / 恐怖）。

## 一、启动

```
cd D:\pythonProject\script-dm
npm install      # 只需第一次执行
npm start        # 或 node server.js
```

浏览器打开 `http://127.0.0.1:3000`。
同一局域网内，手机/其他电脑访问 `http://本机IP:3000` 即可加入。

也可以直接双击 `启动服务.bat`。

## 二、怎么跑一局（演示流程）

**第 0 步 · 先选本**（入口页最上面那块）
- 「我的文件」：拖一个 Word 进来，或点「选整个文件夹」一次把整本剧本的素材全选上，平台会解析成「角色 + 分幕 + 线索」；
- 「剧本库」：4 本内置剧本（雨夜旧屋 / 蝉鸣未歇 / 长夜宫宴 / 第七间病房），点一下就能直接开局；
- **「自动生成」**：只填两样东西 —— **参加人数（3–8 人）** 和 **想要的风格**（雨夜悬疑 / 古风宫廷 / 校园青春 / 恐怖惊悚 / 民国恩怨），平台当场生成一整本：每人有身份、性格、与死者的关系、不愿说的事，外加 4 条任务（真凶多一条"你是真凶…"）；三幕公开剧情 + 每人每幕的专属视角 + 每幕 2 条公开线索和最多 4 条私人线索 + 结局与复盘；书名可留空自动取；
- 「粘贴 / 链接」：把剧本正文贴进去，或贴一个网页链接让平台抓正文；
- 解析 / 生成完先看预览（书名、类型、几个角色、几幕、每幕几条线索、解析警告），再选画风，点「用这个本开新房间」。
- 什么都不选也能玩：默认用内置《雨夜旧屋》。

1. 窗口 A：确认剧本 →「新建房间」拿到房间号（例如 R4F9K），昵称填 `DM`，点「以中控 DM 进入」。
2. 窗口 B/C/D：房间号填同一个，昵称分别填 `阿楠`、`小周`……，点「以玩家进入」。
3. 玩家在自己窗口里选角色（先到先得）。
4. 中控点「正式开本」：
   - 每位玩家自动收到「**人物档案**（身份 / 性格 / 与死者的关系 / 不愿说的事）+ 你的任务 + 三条扮演小提示」和「第 1 幕剧本」，屏幕中央弹出「新一轮开始 · 第 1 幕」，纸条自动摆进托盘；
   - AutoDM 模式下，中控台顶部有一条**倒计时条**告诉你机器人下一步要做什么、还剩多久（分钟级倒计时）；按时间轴自动推送下一幕、发放线索、开启投票、结算、放复盘。
5. 想自己控节奏：把主控模式切成「人工介入」，机器人立刻暂停、倒计时条消失，改由你点「推送本幕」「一键发放本幕线索」「开启投凶」。
6. 想改机器人的节奏：中控台 ③ 区下方「机器人的时间间隔（分钟）」四格（推幕后多久发线索 / 两条线索之间 / 每一幕间隔 / 最后一幕到投票），改完点「保存节奏」，从下一幕起生效。

## 三、四项核心需求的实现位置

### 1）机器人全程接管 / 可人工介入
- 服务端 `scheduleAuto()` 按 `script.autoTiming` 排定时间：
  `clueDelay`（推幕后多久发线索）、`clueGap`（线索间隔）、`actGap`（每幕间隔）、`voteDelay`（最后一幕多久后开投票）。
- 前端 `setAuto` 事件一键切换；切人工时 `clearTimers()` 立刻清空所有待执行动作（含 `room._plan` 倒计时计划），已发出的内容不受影响。
- 切回 AutoDM 时从 `当前幕 + 1` 继续，不会重发已经推送的幕。
- **时间间隔可设置**：新事件 `setTiming{clueDelay,clueGap,actGap,voteDelay}` 写入剧本的 `autoTiming`，边界由 `normTiming()` 收敛（内部存秒、界面按**分钟**填：`clueDelay/clueGap` 0.5–60 分钟，`actGap/voteDelay` 1–120 分钟，步进 0.5 分钟），填 0 或负数不会把节奏打乱；正在 AutoDM 且已开本时会立刻按新参数重排下一幕。
- **倒计时 + 新鲜轮提示**：`scheduleAuto` 内部把每个动作同时记进 `room._plan`（`{at,done,kind,actIdx,label}`），`buildState` 把最早未完成的一条作为 `autoNext{label,actIdx,at,leftMs}` 下发；前端据此每秒本地推算，不轮询服务端。中控台顶部 `auto-bar`、玩家页顶部 `pl-auto-bar` 显示「下一步是什么 + mm:ss + 进度条」，剩 10 秒变红脉冲、到点变灰，切幕瞬间闪三下；同时服务端对全房间发 toast「第 N 幕开始了：<幕标题>」，玩家端弹出「新一轮开始 · 第 N 幕」。
- 服务重启后 `server.listen` 回调会把进行中的 AutoDM 房间重新排回时间轴，倒计时不会停在 00:00。

### 2）居中弹窗 + 独立放大
- 收到剧本 / 线索 / 扶车 / 投票 / 结算 → 屏幕正中弹窗（`showPopup()`），带对应图标与「去托盘查看」。
- 每张纸条有「放大」按钮 → 独立阅读窗口（`openZoom()`），支持 A+ / A− 调字号，长文可滚动。

### 3）托盘与线索梳理
- 每拿到剧本段落、线索、任务卡，服务端 `pushTrayItem()` 建纸条并自动分配初始坐标。
- 客户端 `startDrag()` 用 Pointer Events 实现自由拖拽，兼容鼠标与触屏；松手时 `updateTrayPos` 落库。
- 「系统整理」按时间顺序 4 列重排（`arrangeTray()`）；玩家手动摆的布局会保存到 `data/rooms.json`，刷新页面仍在。
- 纸条配色区分：剧本（米白）、线索（浅黄）、任务（浅粉）。

## 五、换成你自己的剧本（Word / 文件夹导入）

不用改代码了。入口页「我的文件」直接上传就行：

- 支持 `.docx`（Word 2007+）、`.txt`、`.md`、`.csv`、`.json`、`.html`，可以多选、也可以整个文件夹一起上传（会按文件名自然排序后合并成一份文本再解析）。
- 解析规则（`scripts.js` 的 `parseTextToScript`）：
  - 书名取《》里的内容，没有就用第一行，再没有就用文件名；
  - 角色段落以 `角色：` / `人物：` / `登场人物：` 开头，下面每行 `名字：描述` 就是一个角色（最多 8 个，遇到「第 X 幕 / 线索：/ 剧情 / 正文 / 复盘 / 凶手 / 真凶」就结束）；
  - 分幕用 `第一幕` `第二幕`… 或 `第1幕`，幕标题就是这一行的文字；
  - 线索用 `线索：名字 内容` 一行一条，按出现顺序轮流分配到各幕；
  - 真凶写成 `凶手是XX` 或 `真凶：XX`，解析后只在中控台可见；
  - 没写到的部分自动补占位角色 / 兜底个人视角，并在预览里用黄色条目告诉你「哪段没识别到」，不会静默出错。
- 老版 `.doc` 不能直接读（会提示「请另存为 .docx」）；图片类文件会被跳过。
- 粘贴正文、粘贴网页链接（`/api/import`，自动抓正文、跟随跳转、15 秒超时）也能出剧本。

不想上传时，也可以直接改 `scripts.js` 里的 `LIBRARY`：

```js
{ id, name, type, theme, intro,
  roles: [{ id, name, avatar, desc, tasks: [...], isKiller }],
  acts:  [{ title, public, personal: { 角色id: 该角色专属剧本 }, clues: [{ id, title, content, to, isPublic }] }],
  ending: { trueEnd, falseEnd }, reveal, hints: { 1, 2, 3 },
  autoTiming: { clueDelay, clueGap, actGap, voteDelay } }   // 单位秒（界面按分钟显示/填写）
```

`clues[].to: "all"` 表示全员获得，写角色 id 表示只发给该角色。真凶由 `isKiller: true` 标记，玩家端永远看不到这个字段。

## 五之二、自动生成一本（只给人数 + 风格）

入口页「自动生成」页签，或者直接调接口：

```
POST /api/generate
{ "count": 5, "style": "ancient", "title": "长安夜宴" }   // style 可省略，title 可省略
→ { "script": {完整剧本}, "warnings": [] }               // 人数越界返回 400 {error:"参加人数请填 3 ~ 8 人"}
```

- 生成器在 `generate.js`，零依赖，导出 `GEN_STYLES`（5 档风格：`night` 雨夜悬疑 / `ancient` 古风宫廷 / `campus` 校园青春 / `horror` 恐怖惊悚 / `paper` 民国恩怨，各带一行 `desc`）和 `generateScript({count,style,title})`。
- 每套风格一套素材池：地点、死者、6 个场景、6 件物品、8 个名字、幕标题与开场、线索标题、关系 / 秘密 / 动机句。生成时随机组合，**角色名去重、真凶随机且不会是第一个角色**（避免一眼看穿），恰好一个 `isKiller`。
- 结构完全兼容内置剧本：`roles[].desc` 是四行「身份 / 性格 / 与死者的关系 / 不愿说的事」，`tasks` 4 条；三幕 = 幕标题 + 现场描述 + 在场名单 + 本幕任务，`personal[角色id]` 每幕一段扮演引导；每幕 2 条公开线索（`to:"all"`）+ 最多 4 条私人线索；`ending.trueEnd/falseEnd`、`reveal`（真凶 + 动机 + 破局关键 + 其他人秘密清单）、`hints` 三档（**不含凶手名**）、`autoTiming{clueDelay:15,clueGap:10,actGap:55,voteDelay:40}`。
- 生成完自动填进预览，确认后「用这个本开新房间」；开本时每个人收到的人物档案就是这本里对应角色的 `desc + tasks`。

## 五之三、接一个 AI 现写（可选，填 Key 即生效）

平台默认用 `generate.js` 的模板组合出本。想要"每次都不一样、文笔更像人写的"，接一个**OpenAI 兼容**的大模型即可，不需要改代码：

1. 把 `data/ai.example.json` 复制成 `data/ai.json`（同目录），填三项就够：

```json
{ "provider": "ark",
  "baseUrl": "https://ark.cn-beijing.volces.com/api/v3",
  "model": "doubao-seed-2-1-pro",
  "apiKey": "你的 Key" }
```

2. 重启服务（`node server.js`）。入口「自动生成」页下方会出现「当前用 AI 写作：…」；没填 Key 就显示「当前用模板生成」。
3. 用环境变量也可以：`ARK_API_KEY` / `DEEPSEEK_API_KEY` / `SCRIPT_DM_AI_KEY`，可再配 `SCRIPT_DM_AI_BASE`、`SCRIPT_DM_AI_MODEL` 覆盖地址和模型。
4. 模型挂了、超时（100 秒）、返回的不是合法 JSON，都会**自动退回模板生成**，预览里用黄色提示写明原因，不会让你开不了本。

**去哪拿 Key**

| 平台 | 入口 | 模型名 | 大致价格（2026-11） |
|---|---|---|---|
| 火山方舟（豆包，推荐） | console.volcengine.com/ark → 「开通管理」开通语言模型 → 「系统管理 → API Key 管理」创建 | `doubao-seed-2-1-pro` / `doubao-seed-2-1-turbo`（也可在模型广场复制 Model ID） | Pro 6 元/百万输入、30 元/百万输出；Turbo 3 / 15；每个模型送 50 万免费 tokens，未开通时有「安心体验模式」，用完即停、不额外扣费 |
| DeepSeek | platform.deepseek.com → 「API Keys」创建 → 充值 | `deepseek-flash` | 闲时 1 元/百万输入、4 元/百万输出；高峰（工作日 9–12、14–18）翻倍 |
| 智谱 GLM | open.bigmodel.cn → API Key | `glm-4.5-air` | 有免费档，付费按 token |

一本 5 人本大约 1–2 万 tokens，按上表价格一本**几分钱到两毛钱**。方舟那 50 万免费额度够写几十本。

**安全**：`data/ai.json` 里有你的 Key，别发给别人、别传公开仓库；怀疑泄漏就去控制台删掉重建一个。平台缓存里没存 Key，只在服务端读文件/环境变量。

## 六、DM 全职 / 兼职

入口页有一个开关「DM 同时以玩家身份参与」：

- **不勾（全职中控）**：只有中控台，不下发剧本、不占角色、不能投票，专心控场、扶车、结算。
- **勾选（兼职中控）**：进入后中控台左侧多一块「我的角色」，先给自己选一个角色；开本后你和玩家一样收到任务卡、每幕剧本、线索，也会弹居中提示、能在托盘里拖纸条、能投凶。
- 中控台右上角有「中控台 / 我的角色」两个页签，随时切换：控场时看中控台，轮到你发言时切到自己的托盘。
- 全职和兼职可以同一房间里共存（比如一个全职 DM + 一个兼职副 DM），两人都能操作推进。

实现要点：`players[name] = { roleId, isDM, plays }`，`plays=false` 的全职中控在推送剧本、线索、任务卡时被跳过（`if (p.isDM && !p.plays) continue`）。

## 七、联机与二维码

1. 服务端监听 `0.0.0.0:3000`，同一局域网内的手机、平板、其他电脑都能访问。
2. 中控台右上「邀请二维码」按钮：弹窗展示二维码 + 房间号 + 局域网地址清单。
   - 二维码内容就是 `http://<局域网IP>:3000/?room=房间号`，手机扫码后房间号自动填好，只需填昵称。
   - 默认优先使用 `192.168.x.x` 的地址。
   - 本机访问仍可用 `http://127.0.0.1:3000`。
3. 接口：`GET /api/net` 返回所有局域网地址；`GET /api/qr?url=...` 返回二维码 PNG（服务端用 `qrcode` 生成，离线也能出图）。
4. 手机扫不开时，多半是 Windows 防火墙没放行 Node。用管理员权限执行一次即可：

```
netsh advfirewall firewall add rule name="script-dm 3000" dir=in action=allow protocol=TCP localport=3000
```

5. 想让**外网**的人也能进来（不在同一 WiFi）：中控台右上「邀请二维码」弹窗里有「**开启公网通道**」按钮，点一下服务端会启动 localtunnel（`localtunnel` npm 包），约 5–10 秒后返回 `https://xxx.loca.lt` 公网地址，二维码自动切换成公网地址，对方扫码/点链接即可跨网络进入，不需要装任何客户端。
   - 公网地址存在 `GET /api/net` 的 `publicUrl` 字段里；开一次就一直在，直到服务重启。
   - 公网通道依赖 external 的 localtunnel 中转，偶尔会慢或临时不可用，重试按钮可重新申请地址。
   - 想更稳可以用 Cloudflare 隧道：`cloudflared tunnel --url http://127.0.0.1:3000`，把返回的 `https://xxx.trycloudflare.com` 手动拼成 `.../?room=房间号` 发给玩家。
   - 公网模式下任何人都能凭房间号进入，只适合熟人车。

## 八、界面风格（手绘纸张拼贴）

- 参考「剧本杀是什么」那张信息图：米色纸张底、牛皮纸卡片、暗红标题、手写感字体、虚线边框、便利贴、胶带压角。
- 玩家端纸条 = 便利贴：剧本（米白）、线索（黄）、任务（浅绿），顶部一小条胶带，轻微倾斜，可自由拖动。
- 弹窗、放大阅读、二维码弹窗、Toast 同一套纸张语言（虚线边 + 胶带 + 微微倾斜）。

### 中控台：六个分区 + 系统提示（这一版的重点）

中控台不再是一堆并排面板，而是一块"按区域操作"的控制板：

| 区域 | 里面有什么 | 你怎么用 |
|---|---|---|
| 📣 系统提示（顶部黄色便利贴） | 自动算出"你现在该做哪一步"，右侧一个大按钮 | 直接点按钮就行，不用自己判断流程 |
| ① 剧情推进 | 每一幕一张卡片，标注「未推送 / 进行中 / 已推送」 | 点卡片上的「推送本幕」把这一幕发给所有人 |
| ② 线索发放 | **只有一个「一键发放本幕线索」按钮** + 一行状态（本幕共 N 条 / 已发 M 条 / 还剩 K 条） | 点一下，本幕所有还没发过的线索同时进对应玩家的托盘；发完按钮变「本幕线索已全部发放」并置灰。想看明细可展开下面的折叠区（默认收起，玩家看不到） |
| ③ 角色席位 | 玩家列表（在线状态、角色、托盘纸条数）+ 我的角色 + 主控模式 + **机器人的时间间隔四格** | 看谁还没选角，切换 AutoDM / 人工，改节奏参数后点「保存节奏」 |
| ④ 投票与结算 | 投票进度 + 三个大按钮 | 开启投凶 → 结算投票 → 放出复盘 |
| ⑤ 扶车与备注 | 轻/中/强三张卡，内容**默认模糊遮住**，卡头写「含剧情指向，确认再打开」 | 全职 DM 可「点开核对」→ 看完「遮回去」→「发送给玩家」；**兼职 DM 看不到原文** |
| ⑥ 托盘巡查 | 选玩家看他的托盘 + 操作日志 | 随时点开某人的纸条读全文 |

系统提示的推进逻辑：未开本→「正式开本」；第 N 幕→「推送第 N+1 幕」；最后一幕→「开启投凶」；投票中→「结算投票」；已结算→「放出复盘」；结束→「已完成」。

线索"已发放"状态由服务端记录（`room.givenClues = { 幕序号: [线索序号] }`，随 `buildState` 的 `dm.givenClues` 下发），刷新页面也不会丢。一键发放走 `giveCluesAct` → 服务端 `giveActClues()` 逐条调 `giveClue()`，只发没发过的，重复点不会重复计数。

**扶车不剧透**：内置剧本的 `hints` 全部改成不点名凶手、不给角色代号的引导句（例如"先别急着指认人，把'谁今晚来过、谁身上带着不属于自己的东西'列出来"）。前端 `.hint-text.masked` 用 `filter: blur(5px)` 遮住，DM 点击「点开核对」才可读；`S.me.plays === true` 的兼职 DM 直接锁死（卡片标记 `locked`，只留「发送给玩家」），私有备注整块换成提示「需要完整中控视角请用另一个窗口开全职中控」。

**画风随本**：每本剧本带 `theme` 字段（`paper` / `night` / `ancient` / `campus` / `horror`，入口页显示为「纸张 / 雨夜悬疑 / 古风 / 校园 / 恐怖」，也可以手动改）。`buildState` 把 `theme` 下发到 `game.theme`，客户端 `render()` 首行 `applyTheme()` 写 `body[data-theme]`，于是**中控台和玩家页都会跟着剧本换底色、按钮、标题色**，纸纹质感保留。上传的自定义剧本在解析后也会自动判类型（`themeOf()`：恐怖 → 古风 → 校园 → 雨夜悬疑 → 默认纸张）。

**手机 / 平板适配**：纸条用 Pointer Events 拖拽（触屏放行、鼠标只认左键、8px 位移阈值区分手抖与轻点、`pointercancel/blur` 兜底防止"卡住"），轻点整张纸条直接放大；`.paper{touch-action:none}` 避免拖动被页面滚动抢走；托盘画布按纸条实际宽度和视口动态撑开，手机上横向滚动，缩窗 180ms 去抖后自动重排；`@media (pointer:coarse)` 把按钮放大到 38px，`@media (max-height:640px)` 保证矮屏弹窗不被裁掉。

- 字体优先 `Kaiti SC / 楷体`，本机没装时回退到微软雅黑，正文依然清晰。

## 九、已修复：玩家进房白屏 / DM 推送玩家没反应

- 现象：以玩家身份进入后页面一片空白；DM 推幕、发线索时玩家端没有任何变化。
- 根因：`client.js` 的 `render()` 在非 DM 分支只调用了 `renderPlayer()`，从没有把 `#screen-player` 从 `hidden` 状态解除；而 `joined` 回调只隐藏了入口页。三个界面全隐藏 → 白屏，弹窗没有承载界面 → 看起来"没反应"。另外 `render()` 开头的 `if (!S) return` 会让 `joined` 之后、`state` 到达之前的首次渲染直接返回。
- 修复：①`render()` 的玩家分支显式显示玩家界面、隐藏中控台；②`joined` 回调里立刻按身份切屏，不等 `state`；③中控兼职玩家切换页签时统一走同一套显隐逻辑。
- 回归测试：`data` 下曾用 jsdom 加载真实 `index.html` + `client.js`，模拟 `joined → state → notify → 增量 state` 全链路，16 项断言全通过（玩家界面可见、托盘纸条数、HUD 数值、弹窗标题/正文、中控玩家列表与按钮显隐）。

## 十、已知边界（当前版本未做）

- 没有登录鉴权：知道房间号 + 昵称即可进入，适合熟人车，不适合公开匹配。
- 剧本解析是**规则式**的，但已按市面上常见的写法做了适配：`角色 N｜名字` / `玩家 A｜名字` / `角色：名字`、`第一幕：标题`、`线索 N：标题` + 下一行正文、线索区里的 `1.标题 正文`、`真凶：XX` / `凶手是XX`；角色块里的 `【公开人设】【你的秘密】【个人任务】【随身物品】【认知】` 会拆成「人物档案（身份/性格/与死者的关系/不愿说的事）+ 个人任务」，并给每一幕生成只发给本人的个人视角。解析不到的地方会在预览里用黄色警告写清楚。
- **文件格式不再只看扩展名**：真正的 `.docx`（zip）、老版 `.doc`/WPS 二进制（OLE，扩展名改成 .docx 也能认）、纯文本/Markdown（扩展名写 .docx 也能读，UTF-8 与 GBK 都试）都会先按文件头判断；老 `.doc` 会用本机 WPS/Word 静默转一次文本，两个都没装时会给出明确提示而不是"不是有效的 docx"。
- 真凶如果**不在玩家角色里**（本格推理的隐藏凶手，例如两三个人的小体量本），解析会保留复盘与线索，但投票无法自动判定，结算页显示「未设定」，需要中控在复盘时口头宣布。
- **自动生成默认是模板组合式**（五套固定素材池随机拼接），同一风格多开几本会看出骨架相似；填了 `data/ai.json` 的 Key 之后就走 AI 现写（见「五之三」），模板只在 AI 不可用时兜底。AI 写本的质量取决于所选模型，偶尔仍可能漏人、幕数偏少，`ai.js` 的 `normScript()` 会自动补齐角色视角、纠正真凶数量和线索归属。
- 「网上搜集的本」目前实现为**内置 4 本 + 粘贴网页链接抓取正文**，没有做联网检索剧本站点；需要更多本可以直接往 `scripts.js` 的 `LIBRARY` 里加。
- 一个房间里换本会**整局重置**（开本状态、位置、托盘、投票全清空），已开本时换本会被拒绝，需开新房间。
- 线索目前是纯文字，图片 / 音频线索需要扩展 `clue` 字段与纸条渲染。
- 无语音、无聊天，靠外部语音工具（如开黑软件）配合。
- 每个房间的坐标是"每人一份"，暂不支持多人共同编辑同一张白板。
- 公网通道基于 localtunnel 中转，无鉴权、带宽一般，不要用来跑敏感内容。
- 断线重连只恢复服务端状态（托盘、坐标、剧本都在），但页面刷新后需要重新点进房间。
- 触屏拖拽只做了逻辑层回归（jsdom 断言），真机 iOS / Android 手感建议实测一轮再定。
